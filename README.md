# ProgettoMagius 公开资源分发

## 玩家下载入口

**所有当前客户端和资源包都集中在同一个 [最新正式发行](https://github.com/HiiragiNemu/ProgettoMagius-1/releases/latest) 中。** 不需要查找或拼装各次 Scenario 迭代发行。

- 日常更新：使用 APP 原有的资源检查及「检查 APK 更新」入口，保留应用数据。
- 手动下载：只从上述同一发行的 Assets 获取需要的文件。完整剧情包为 `cn_scenario_update.zip`，完整脚本包为 `cn_js_update.zip`，累计补充包为 `cn_js_delta.zip`；包名和原有安装入口保持不变。
- 累计补充包中包含部分剧情文件是既有兼容设计。当前发布流程检查它们与完整剧情包的同路径内容一致，避免最后安装补充包时覆盖成旧剧情。不要混用以前另存的补充包与新发行的完整包。
- 文件没有内容变化时会保留原附件及摘要，不会为了刷新日期重传。判断当前版本请以本发行的版本清单及校验值为准，不以 GitHub 的「几天前」提示为准。

历史验证及回退发行转为维护端草稿留存，不作为玩家下载步骤；当前 `latest` 的下载地址保持兼容。

## 维护说明

此仓库用于承接客户端运行所需的公开下载产物；源代码仓库未来转为私有时，玩家不应需要 GitHub 登录或访问令牌。

迁移准备尚不代表已经可以将旧资源仓库设为私有。保持现有线上版本、资源名称、安装标记和已验证的下载入口不变。

迁移顺序：核对玩家下载清单 → 建立白名单同步与哈希校验 → 验证新仓库匿名下载 → 接入客户端和现有代理的双入口 → 完成无旧仓库公开访问的演练后再切换。

## 分发约束

- 只同步已公开且属于客户端下载清单的 Release 附件，不公开源代码、构建秘密、草稿 Release、审计资料或内部调试产物。
- 数据包先于其版本清单发布；下载字节、大小与校验值必须对应。不得仅提升版本号。
- 私有源访问凭证仅留在 GitHub Actions，绝不写入 APK、公开配置、URL、日志或下载产物。
- EdgeOne 等既有镜像继续保留。优先建立原 GitHub 独占资源与配置、版本元数据的独立公开入口。

字体替换与客户端版本发布须各自通过检查，不能以完成资源同步代替验收。
