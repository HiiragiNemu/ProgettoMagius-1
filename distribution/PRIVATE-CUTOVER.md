# 旧资源仓私有化兼容（1.0.196）

基线：客户端 1.0.195。保留已审核的替代字体、许可、Web 字体及字号；不改 Connecting，不操作设备。

- 玩家线路：匹配文件身份的 EdgeOne → ESA → Cloudflare → ProgettoMagius-1 → 旧仓应急。手动选择普通线路仍有效。
- 每个文件共享一次有限轮次，跨分片与下载引擎最多尝试五个不同源。旧仓仅末级一次，失败保留进度，显式重试才开启下一轮；401/403/404 不请求登录。
- 更新查询共 6.5 秒；先收集普通源，完整且可信的同版大小/哈希一致才使用。普通源全部失败才查询旧仓。
- Cloudflare 新公开仓优先，旧仓应急；每个上游建立响应最多 2 秒，元数据包括读取时间。正常大文件传输不设总时间上限；验证 Range 并直接流式返回。
- 两个配置上游失败时，返回随部署保存的已核验配置快照。该快照不是文件镜像，GitHub 整体不可达时并不保证所有文件仍能下载。
- 发布先上传并核验两个仓库的 APK/元数据，再提升来源仓版本，执行来源仓持有的同步脚本，最后核验公开配置。定时同步与客户端发布共用并发锁，避免相互覆盖。
- 本次不创建 R2 或付费资源。EdgeOne/ESA 冷回源独立性未经本任务证明，失败时继续后级公开链路。

验收：主机 Java/DEX、来源轮次、Worker 故障模拟、匿名网络和发布记录；手机视觉/播放/安装验收由用户执行。
回滚：使用交付目录中按文件校验的 rollback.py；生产 Pages 可回到记录的前一成功部署。版本门槛不得随意回退，已发布客户端需要新的修正版。
