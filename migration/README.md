# 私有化前的资源迁移

## 同步范围

`tools/mirror_release.py` 的固定白名单覆盖下载页的 16 个 ZIP、正式 APK、8 个版本/校验 JSON；另允许两份已知 APK 构建叠加包。不同步整个源码仓、不复制草稿或预发行 Release、不复制任意新增附件。新运行时资源须经审阅加入白名单。

先同步累计补充包、APK、剧情和完整 JS，再处理基础、语音和视频包，版本 JSON 最后更新。大包逐个流式下载和上传，不要求磁盘同时容纳完整资源集合；相同大小与 SHA-256 的目标附件不重复传输。

## 自动执行与私有源凭证

本仓库提供 `.github/workflows/mirror.yml` 可复用工作流。唯一自动写入者是来源仓库的同步工作流：上游发布完成后以及每小时调用，使用固定提交 SHA 锁定此处代码。

来源仓库的工作流令牌只读取该来源仓库；目标写令牌通过 Actions 的显式 secret 参数传入。在来源仓库转私有后仍由来源仓库内的工作流读取 Release，再上传这些获准公开的产物。因此不依赖匿名读取私有仓库，也不需要将凭证放入此公开仓、APK 或代理。

若现有目标写凭证不覆盖新资源仓，需要维护者在 GitHub 设置中调整授权范围；不要在聊天、代码或配置中粘贴令牌。GitHub 的仓库权限与工作流中某个具体凭证的可访问范围是两件事。

## 公开控制面

全部附件检查后，才提交 `legacy/config.json` 与 `migration/last-sync.json`。公开配置保留原有加速镜像、参数和版本身份，增加新仓库镜像，并将 APK、离线下载及退役分支回主线链接改到新仓库。

传输失败会尝试恢复此次替换的目标附件。检测到来源在同步期间变化则拒绝提交新配置。GitHub Release 多附件上传不是原子事务；短暂同步期间客户端仍须保留既有大小、MD5/SHA-256 和签名校验。同版本不同字节及版本回退均被拒绝。

## 双入口代理

`distribution/_worker.js` 保留现有路径和旧源优先级，在旧源 404、连接失败或不支持 Range 时尝试新公共源；HEAD、206、304、416、流式返回和凭证隔离保留。它是待部署到原代理入口的代码，不代表将文件提交到 GitHub 就已在 Cloudflare 生效。

旧 APK 中写死的原 GitHub URL 不会因另建仓库自动重定向。保护旧 APK 需要部署这份兼容代理或让玩家先升级包含新内置入口的 APK。不能以源仓当前仍公开时测试成功，冒充私有化演练通过。

## 切换前必须全部验收

1. 同步报告成功，25 个必需附件与来源大小、SHA-256 一致，全部能匿名 Range 下载。
2. 新公开配置匿名可读，APK 版本、大小与 SHA-256 和旁注一致。
3. 新 APK 在禁止旧仓库访问的条件下仍能取配置、发现更新、下载累计包，并能执行全新安装和断点续传。
4. 原 Cloudflare 兼容入口已部署且实测能在旧源 404 时回退。EdgeOne/ESA 冷缓存回源也须独立核实，缓存命中不算。
5. 字体替换单独检查原字体字节残留、音乐符号及游戏显示；此资源镜像报告不声称旧版 APK 已完成字体替换。

上述验收前，不修改来源仓库可见性，也不提前把客户端版本提升到 194/195。当前实现不重写字体路径，不改变安装标记的规范 URL，不改资源包内部字节。
